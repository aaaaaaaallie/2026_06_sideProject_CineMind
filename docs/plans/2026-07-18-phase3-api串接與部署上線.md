## 步驟

### 1. 使用者手動申請（外部帳號，無法代辦）

- [ ] Vercel 註冊並匯入此 repo（[vercel.com](https://vercel.com)，可用 GitHub 登入）。
- [ ] Vercel 專案 Storage 頁安裝 **Upstash Redis**（免費方案）→ 複製 `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` 填入本機 `.env`（本機與線上共用同一 instance）。

### 2. 產生自製密鑰（經使用者同意後執行）

- [ ] `TELEGRAM_SECRET_TOKEN`：`openssl rand -hex 32` 產生並寫入 `.env`。
- [ ] `DASHBOARD_TOKEN`：亂數產生並寫入 `.env`（這是使用者登入 Dashboard 要輸入的密碼，長度取好記與安全的平衡）。

### 3. 金鑰實測（需連外網，經使用者同意後執行）

- [ ] Gemini：最小 generateContent 請求，確認 200。
- [ ] Telegram：`getMe`，確認 200 且回傳 bot username（同時驗證重組的 token 無誤）。
- [ ] OMDb：`?t=Inception&apikey=...`，確認回傳正確資料（key 已 email 開通）。

### 4. 本機閉環測試

- [ ] `npm run dev:bot` 啟動，對 bot 發訊息，從 log 取得 chat id → 填入 `TELEGRAM_ALLOWED_CHAT_ID`。
- [ ] 跑 [TESTING.md](../TESTING.md) 的「指令流程」「辯論」「/generate 三段鏈」清單。

### 5. 部署與 webhook 綁定

- [ ] 安裝 vercel CLI（本機目前沒有）或改用 git push 觸發自動部署。
- [ ] Vercel dashboard 設定全部 8 個環境變數（Upstash 兩項由 Marketplace 整合自動注入則免手動）。
- [ ] `vercel --prod` 部署。
- [ ] `setWebhook` 帶 `secret_token` + `drop_pending_updates=true` 綁定；`getWebhookInfo` 確認 `last_error_message` 為空。

### 6. 線上驗收

- [ ] 跑 TESTING.md「部署後（webhook 模式）」清單。
- [ ] Dashboard 線上驗證：正確 token 進站、真實 reviews 渲染、375px 實機版面。
