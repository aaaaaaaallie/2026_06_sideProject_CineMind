# Phase 0 + 1 — 環境準備與 Bot 後端閉環（已完成 ✅）

> 原始計畫「CineMind Admin 專案規劃大綱」步驟 1–4。完成日：2026-07-17。

## 目標

打造「對話 → 辯論 → 結構化歸檔」的後端閉環：Telegram 隨身輸入、Gemini 硬核影評人辯論、`/generate` 三段式觀點打造、JSON 沉澱至 Redis。Dashboard（步驟 5）不在此計畫範圍。

## 步驟與完成狀態

### 步驟 1：環境準備與免費用量卡位 ✅

- [x] Telegram Bot：@BotFather 建立，取得 `TELEGRAM_BOT_TOKEN`。
- [x] Gemini API Key：Google AI Studio 免費金鑰。
- [x] OMDb API Key：Free Key（1,000 req/day）。
- [x] Vercel 帳號 + Redis：**實作差異** — 採 Vercel Marketplace 的 Upstash Redis（非原計畫的 Vercel KV），env 為 `UPSTASH_REDIS_REST_*`，程式碼 fallback 讀 `KV_REST_API_*`。

### 步驟 2：數據對齊與思辨中介層 ✅

- [x] 多語言實體對齊：中文片名 → Gemini 轉標準英文片名與年份（`omdb.js alignAndFetch`）。
- [x] 官方數據掛載：OMDb 撈海報、年份、Genre；帶年份失敗去年份重試；快取 30 天；miss fallback。
- [x] 刁鑽對話引導：硬核影評人 persona（`prompts.js`），反問不附和；對話 history 存 Redis session（TTL 48h、上限 40 則）。
- [x] 辯論回覆 `thinkingBudget: 0` 維持秒級回應。
- [x] Stretch：語音輸入（`gemini.js transcribeAudio`）。

### 步驟 3：部署 Webhook 與即時對話測試 ✅

- [x] `api/telegram.js` webhook endpoint + secret token 驗證。
- [x] **實作差異** — 原計畫「限制 10 秒內響應」，實作改為 `maxDuration: 60` + webhook 永遠回 `200 {}` + 回覆用 `sendMessage` 主動送，徹底避開響應時限與重送風暴。
- [x] 另補本機開發模式 `npm run dev:bot`（long-polling 免 tunnel，自動 deleteWebhook）。
- [x] 冪等鎖與 chat id 白名單（原計畫未列，安全前置補上）。

### 步驟 4：觀點打造器（Debate Engine）✅

- [x] `/generate` 觸發，ack-then-process（`waitUntil` 背景執行）。
- [x] 階段 A 盲點挖掘（thinking 512）→ 階段 B 論點對撞（thinking 512）→ 階段 C 風格重塑（thinking 1024），`debate.js runDebateEngine`。
- [x] 數據沉澱：digest + genres + 年份 + 海報 + timestamp 打包 JSON 存 `review:{id}`（無 TTL），`reviews:ids` 列表索引。
- [x] 附帶：`/list` 最近 5 筆、`/cancel` 放棄討論、`GET /api/reviews`（Bearer token）供 Dashboard 讀取。
