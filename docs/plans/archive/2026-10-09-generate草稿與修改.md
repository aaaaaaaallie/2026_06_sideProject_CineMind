# /generate 改為「草稿 → 修改 → 確認歸檔」

## Context

現在 `/generate` 跑完三段鏈就立刻 `saveReview` + `clearSession`（`api/_lib/debate.js`）。對文章不滿意時，對話已經被清掉，只能重新 `/movie` 從頭聊。

使用者決定：
- **草稿制**：`/generate` 只產出草稿、保留 session，確認後才歸檔。
- **兩種修改路徑**：(1) 直接打字給修改意見 → 只重跑 Stage C 改寫（1 次 Gemini 呼叫，省額度）；(2) 退回討論模式多聊幾輪，再 `/generate` 整條重跑。
- 不做 Dashboard 手動編輯 digest。

## 新的使用流程

```
/generate ──► 三段鏈 ──► 送出草稿 + 提示
                         │
   ┌─────────────────────┼──────────────────────┐
   │ 直接打字（修改意見） │ /back                 │ /save
   ▼                     ▼                      ▼
 只重跑改寫（Stage C'）  丟掉草稿、回討論模式     歸檔 + 清 session
 送出新草稿              （之後再 /generate）
```

- 有草稿時 `/generate`：用目前 history 整條重跑，覆蓋舊草稿。
- `/cancel`：照舊清 session（草稿一併丟掉）。

## 步驟

### 0. 計畫檔
依專案流程建立 `docs/plans/2026-10-09-generate草稿與修改.md`（目標 / 步驟 / 驗證清單，內容即本計畫）。

### 1. `api/_lib/session.js` 形狀擴充（不改函式）
session 多一個選填欄位：
```js
draft: { digest, blindspots, clash, revisions: [instruction, ...], createdAt }
```
`setSession` 每次寫入都會刷新 48h TTL，草稿存活規則跟 session 一致。

### 2. `api/_lib/prompts.js`
- 把 `stageCPrompt` 內「任務：…」以下的文章規則抽成共用常數 `ARTICLE_RULES`，`stageCPrompt` 改用它（輸出不變）。
- 新增 `revisePrompt(session, draft, instruction)`：給 movieHeader、逐字稿（模仿語氣用）、盲點、對撞、**目前草稿**、使用者修改意見。要求：只按修改意見調整，沒被點到的段落盡量保留原文；仍遵守 `ARTICLE_RULES`，但修改意見與規則衝突時（例如「縮到 400 字」）以使用者為準；只輸出文章本身。

### 3. `api/_lib/debate.js` 拆成三個函式
- `runDebateEngine(chatId, session)`：A→B→C 後**不歸檔**，寫入 `session.draft` → `setSession` → 送草稿 → 送提示：「這是草稿，還沒歸檔。直接回修改意見我會改寫；`/back` 回去繼續討論；滿意就 `/save`。草稿 48 小時內有效。」失敗訊息保留現有寫法。
- `reviseDraft(chatId, session, instruction)`：`generateText(revisePrompt(...), { thinkingBudget: 1024 })` → 更新 `draft.digest`、push instruction 進 `revisions` → `setSession` → 送新草稿 + 簡短提示。失敗時草稿不動，回錯誤訊息。
- `saveDraft(chatId, session)`：把現有的 review 組裝邏輯（id、wordCount、`stages: { blindspots, clash }`…）搬過來，改讀 `session.draft` → `saveReview` → `clearSession` → 回「✅ 已歸檔」。`countWords` 沿用。
- 錯誤訊息用 `bot.js` 的 `aiErrorMessage`（改為 export 或搬到共用處），讓額度用完時提示清楚，符合 DEVELOPMENT.md 的規則。

### 4. `api/_lib/bot.js` 路由
- 新增 `/save`、`/back` 路由（放在 `/generate` 附近）。
  - `/save`：無草稿 → 「目前沒有草稿，先 /generate」；有 → `saveDraft`（只是 Redis 寫入，直接 await 即可）。
  - `/back`：無草稿 → 提示；有 → `delete session.draft` → `setSession` → 「已回到討論模式，聊完再 /generate」。
- `handleDebateTurn` 前分流：`session.draft` 存在時，純文字 → `handleRevise`：先 ack「✏️ 照你的意見改寫中…」，再 `waitUntil(reviseDraft(...))`（有 thinking，沿用 ack-then-process 規則）。
- `handleGenerate`：有草稿時 ack 文字改成「重新打造（會覆蓋目前草稿）」。
- **處理中鎖**：`/generate` 與修改都先 `SET chat:{chatId}:busy 1 NX EX 120`，拿不到就回「上一個請求還在處理，稍等一下」；`runDebateEngine` / `reviseDraft` 結束（`finally`）時 `del`。避免連打兩次修改意見時兩個背景任務互相覆蓋草稿。
- `/start` 說明文字加上 `/save`、`/back` 與「草稿可直接回覆修改意見」。

### 5. 文件
- `docs/FEATURES.md`：`/generate` 段改寫成草稿流程，新增 `/save`、`/back` 小節。
- `docs/ARCHITECTURE.md`：session JSON 加 `draft`；Key Schema 加 `chat:{chatId}:busy`；`/generate` 資料流與 `debate.js` 職責更新；bot.js 指令清單補 `/save` `/back`。
- `docs/TESTING.md`：`/generate` 區塊換成下方驗證清單。
- `docs/CHANGELOG.md` `[Unreleased] ### Changed` 最上面加一條（2026-10-09）。
- 完成後計畫檔移入 `docs/plans/archive/`。
