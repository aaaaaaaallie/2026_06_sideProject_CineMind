# /movie 支援逗號補充英文片名/年份，降低 OMDb 查無機率

## 目標

`/movie <片名>` 原本只吃一段中文片名，靠 `alignAndFetch()`（`api/_lib/omdb.js`）呼叫 Gemini 猜出官方英文片名與年份，再用猜出來的英文片名查 OMDb。實測發現：片名籠統、少見、或有多部同名作品時，Gemini 容易猜錯英文片名或年份，導致 OMDb 查無（`omdbMiss`），必須整段話重打。

目標：讓使用者在 `/movie` 就能主動補充英文片名/年份，跳過或輔助 Gemini 的猜測，提高命中率。不做：類型（genre）輸入欄位——OMDb 比對用不到，且比對成功後類型會直接被 OMDb 回傳值蓋掉。

格式：逗號分隔（同時接受全形「，」與半形「,」），順序固定為 `片名, 英文片名, 年份`，後兩欄可留空。

## 步驟

1. `api/_lib/omdb.js` — `alignAndFetch(zhTitle, hint = {})` 加可選 hint 參數：有 `hint.englishTitle` 時完全跳過 Gemini 對齊呼叫，直接查 OMDb；只有 `hint.year` 沒有英文片名時，把年份線索塞進 Gemini prompt 輔助消歧，且最終查詢優先採用使用者給的年份。`fetchOmdb()` 不變。
2. `api/_lib/bot.js` — `handleMovie` 用 `rawTitle.split(/[,，]/)` 解析出片名/英文片名/年份三欄，傳進 `alignAndFetch` 的 hint；查無此片的警告訊息加上補充英文片名/年份的提示；`handleStart()` 說明文字加一行提示。「聊聊《X》」自然語言捷徑維持不變，不支援逗號補充。
3. 文件同步更新：`docs/TESTING.md` 新增 4 條驗證項目、`docs/CHANGELOG.md` 的 `[Unreleased]` Added 加一條（2026-08-24）、`docs/FEATURES.md` 的 `/movie` 說明段落補充新格式。

## 驗證清單

用 `npm run dev:bot` 本機 long-polling 手動測，測完跑 `npm run webhook:set` 綁回正式站：

- [x] `/movie 全面啟動, Inception, 2010`／`/movie 一場悲劇, Obsession, 1976`（片名+英文片名+年份都給）：直接命中 OMDb，跳過 Gemini 對齊呼叫，撞名不同年份也能精準區分（同時驗證 `Obsession` 1976/2025/2026 三個不同年份版本各自命中對的電影）。
- [x] `/movie 全面啟動, Inception`（只給英文片名）：略過年份也能查到正確的片（cache key `omdb:title:inception:` 命中 tt1375666）。
- [x] `/movie 全面啟動, , 2010`（只給年份線索）：年份線索有效塞進 Gemini prompt 輔助消歧，且最終查詢年份採用使用者給的值（cache key `omdb:title:inception:2010`，非 Gemini 自己猜的年份格式）。
- [x] `/movie 星際效應`（完全不變的舊格式）：回歸測試通過，觸發兩次 Gemini 呼叫（對齊猜測 + 開場白）與改動前一致，未被新邏輯影響。
- [x] `/movie` 空片名：錯誤提示文字正確顯示，不噴例外。

備註：最初用計畫草稿裡的範例片名「大濛／Op O」測試，因為那是規劃時隨手掰的示範片名、現實中不存在，導致兩次測試都合理地查無此片；改用真實電影（全面啟動/Inception、Obsession 系列撞名片）重測後才驗證到位。
